## 4. データ構成

すべて JSON。**個人情報（氏名・予約番号・電話）はリポジトリに入れない。** 旅程は端末内だけに保存。

| データ | 置き場所 | 中身 | 作り方 |
|---|---|---|---|
| スポット `spots.json` | リポジトリ（公開） | 既存の項目（id・名前・県・カテゴリ・緯度経度・滞在目安・11月見どころ・車なしOK・説明・出典）に **追加**：`tags`（雨OK／夜／紅葉 など）、`needs_check`（要確認か）、`hub`（最寄りの主要都市 id） | 既存69件に手でタグ付け（1〜2時間）。「要確認」は november_highlight の文言から機械的に拾い、手で直す |
| 主要都市 `hubs.json` | リポジトリ | 主要都市・駅の id・名前・緯度経度（12か所前後） | 手入力 |
| 公共交通の目安 `transit.json` | リポジトリ | 主要都市の組ごとに：目安分数（幅つき）、手段の説明（例「九州新幹線」）、`realistic`（現実的か）、注意（要予約・本数少・運休 など） | 02 の3章の表を写す。阿蘇↔高千穂・阿蘇↔由布院は「現実的でない・要確認」、人吉方面は「肥薩線運休→バス」 |
| 車の所要時間 `car_matrix.json` | リポジトリ | スポット69件＋主要都市の全組み合わせの車の分数・距離 | OSRM 公開サーバの table 機能で一括計算（1秒1回を守る）。数回に分けて取得 |
| 平年値 `normals.json` | リポジトリ | 主要都市ごと・日ごとの平年の最高/最低気温・降水量 | Open-Meteo Historical で過去10年程度の 11/14〜24 を取得して平均 |
| 天気キャッシュ | 端末（localStorage） | 場所ごとの最新の予報（Open-Meteo・気象庁）と**取得時刻** | アプリが取得のたびに上書き |
| 旅程 | 端末（localStorage） | ★行きたい一覧、日付ごとの拠点・スポット順・メモ | アプリ内で操作。書き出し／読み込み（A5）で消失対策 |

**電車・バスの時間の出し方**：スポット A → B のとき、A の最寄り主要都市 → B の最寄り主要都市の目安を表示し、「◯◯駅〜◯◯駅の目安。駅からの移動は別」と添える。正確な便は Google マップの乗換案内リンクで見る。

## 5. 技術構成

技術リサーチ（03）のおすすめ構成をそのまま採用し、2点だけ修正する。

| 部分 | 使うもの |
|---|---|
| 形 | 素の HTML＋JavaScript の1ページアプリ（ビルド不要）。PWA（manifest＋Service Worker） |
| 配信 | GitHub Pages（HTTPS・無料） |
| 地図 | Leaflet＋地理院タイル（標準）。OSM 標準タイルに切り替え可。地図タイルはオフライン保存しない |
| スポット検索 | 自前 JSON をアプリ内で絞り込み。詳細・営業時間は Google マップ検索リンク |
| 車の時間 | 事前計算した `car_matrix.json`（OSRM）。ナビは Google マップの経路リンク（driving） |
| 公共交通 | 手入力の `transit.json`＋Google マップの経路リンク（transit） |
| 天気 | Open-Meteo 予報（16日、緯度経度指定、daily に sunset も含める）＋気象庁の府県予報 JSON（11/18 まで）＋`normals.json` |
| 現在地 | ブラウザの位置情報（HTTPS で） |
| 保存 | localStorage（天気キャッシュ・旅程） |

**03 からの修正点**
1. **Leaflet 本体は CDN ではなくリポジトリに同梱**する（Service Worker で確実にオフライン保存するため）。
2. **その場での OSRM 計算はしない**（デモサーバは保証なし・1秒1回）。アプリ内の車時間はすべて事前計算した表から出し、表に無い組み合わせ（現在地から等）は Google マップのリンクに任せる。

**気象庁の府県コード**（予定）：福岡 400000／佐賀 410000／長崎 420000／熊本 430000／大分 440000／宮崎 450000／鹿児島 460100（鹿児島は奄美と分かれているため、取得して確認する）。気象庁の取得に失敗しても Open-Meteo だけで画面が成り立つ作りにする。

| **予報範囲外・精度の低い日** | 11/19 以降の予報は外れやすい。気象庁の週間予報は 11/18 まで | 11/19 以降は「参考」バッジ＋平年値を並べる。毎朝・毎晩「更新」を押す運用。取得時刻を必ず表示 |
| **公共交通の時刻** | アプリ内の数字は目安で、本数の少ない路線（豊肥本線・高千穂方面のバス等）で乗り遅れると詰む | アプリの数字は「目安・乗換待ち含まず」と明記。実際の便は Google マップの乗換案内で確認。最終便は日ごとのメモ欄に前夜に書く。現実的でない区間はそう表示。肥薩線運休を反映 |
| **車の時間が短めに出る** | OSRM は渋滞を考えない。三連休の由布院・高千穂・太宰府周辺で大きくずれる | 「渋滞なし・目安」と表示し、1.2〜1.3倍を勧める。出発直前は Google マップのナビで確認 |
| **オフライン（山あい・圏外）** | 地図・天気が取れない | アプリ本体・データ・最後の天気は保存済み。地図は自動でリスト表示へ。Google マップのオフラインマップ（P-7）を併用。GPS は圏外でも動くので「近い順」は使える |
| **電池** | 地図表示・位置情報の常時取得で電池が減る | 位置情報は「近い順」を押したときだけ1回取得（常時追跡しない）。地図は開いたときだけ読み込む。モバイルバッテリー持参（P-5） |
| **データの誤り・古さ** | 要確認のイベント、概算の座標、営業時間なし | 要確認バッジと出典リンクを表示し、確認済みに見せない。営業時間は Google マップで見る。主要スポットの座標を目視確認（P-8） |
| **旅程データの消失** | localStorage は消えることがある・端末ごと | 書き出し／読み込み（A5）を 11/14 朝までに入れる。入るまではスクリーンショットで代用 |
| **旅程が公開される** | GitHub Pages の公開リポジトリは誰でも見られる | 旅程は端末内のみ。予約番号・氏名・電話はどこにも入れない |
| **外部サービスの仕様変更・停止** | 気象庁 JSON の仕様変更、OSRM デモの停止 | 気象庁が失敗しても Open-Meteo だけで表示。OSRM は事前計算済みなので旅行中は不要 |
| **開発が間に合わない** | 11/13 夜に Must が揃わない | 2章の「削り方」の順に削る。天気・所要時間・リスト検索は最後まで残す |
| **火山・規制** | 阿蘇中岳・霧島・桜島の立入規制 | 第2段階でリンク集（F25）。それまでは当日朝に気象庁・自治体サイトを見る |

## 付録：MVP 機能一覧（まとめ）

1. 探す画面（地図／リスト、県・カテゴリ・タグ絞り込み、文字検索、今ここから近い順）
2. スポット詳細（11月の見どころ、要確認バッジ、出典、Google マップ経路ボタン、★・日付追加）
3. 所要時間（車＝OSRM 事前計算、電車・バス＝手入力目安、Google マップ経路リンク）
4. 11日間の天気（Open-Meteo＋気象庁 11/18 まで、11/19〜は参考＋平年値、取得時刻表示）
5. 行きたい・日付割り当て（簡略旅程、日ごとの拠点とメモ）
6. オフライン対応（PWA、圏外はリスト表示）
7. 出典・ライセンス表示
