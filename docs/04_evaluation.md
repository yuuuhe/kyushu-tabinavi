# 04 機能評価（九州旅行アプリ 2026/11/14〜24）

- 評価日：2026-11-11（出発まで実質 **2日半**。11/13 夜までに動くものが必要）
- 入力：`01_proposals.md`（50案）、`02_kyushu_research.md`、`data/spots.json`（69件）、`03_tech_research.md`
- 前提として採用する構成（03の結論）：静的 PWA + GitHub Pages、Leaflet + 地理院タイル、車は OSRM で事前計算、公共交通は **無料APIなし → 手入力の目安時間 + Google マップ深リンク**、天気は Open-Meteo + 気象庁週間予報。API キー・課金アカウントは使わない。
- 事実の扱い：提案担当は Web 検索をしていないため、API 名・イベント情報は 02/03 を優先した。提案が Google Routes / Places / NAVITIME / 駅すぱあと / Mapbox / ホットペッパー / Spotify / LLM API など**キー必須・有料の API を前提にしている案は実現性 F を下げた**。提案文に「または手作業データ／リンク」などの代替が書いてある場合は、その実現可能な形で採点し、理由欄に明記した。

## 評価軸
- 価値 V：この旅行（11/14〜24・九州・不慣れ）でどれだけ役立つか。必須要望（①探す ②所要時間 ③天気）に関わる案は加点
- 実現性 F：無料API・既存データで作れるか、精度は十分か
- 工数 E：11/14 までに作れるか（5=数時間、1=数週間）
- 確実性 R：データが古い・間違うリスクの低さ
- **総合 = V×2 + F + E + R（最大25）**

## 3. リスク・落とし穴

### 移動時間
- **公共交通の正確な時刻・所要時間はアプリ内で出せない。** 無料の経路 API が無く、九州の GTFS も整備不足。アプリ内の数字は「02の手入力目安（乗換待ちを含まない）」と明記し、実際の便は Google マップの乗換案内リンクで確認する運用にする。
- 地方の路線（豊肥本線、高千穂方面バス、阿蘇↔由布院など）は本数が極端に少なく、目安時間だけ見て動くと詰む。02 で**要確認**の区間（阿蘇↔高千穂、阿蘇↔由布院）は「公共交通は現実的でない」と表示すべき。
- JR肥薩線（八代〜吉松）は運休が続いている。手入力データに反映し忘れないこと。
- **OSRM は渋滞を反映せず短めに出る。** 三連休（11/21〜23）の由布院・高千穂・太宰府周辺では大きくずれる。表示に「渋滞なし・目安」と付け、1.2〜1.3倍の余裕を勧める。デモサーバは保証なし・1秒1回なので、出発前に `/table` で一括計算して JSON に保存しておく。
- spots.json の**緯度経度は未検証の概算**。距離順や OSRM の計算は大きくは狂わないが、ジオフェンス（到着判定）に使うと誤判定する。主要スポットは出発前に地図上で目視確認したい。

### 天気
- Open-Meteo の16日予報で旅行全日の数字は出るが、**11/19以降は精度が低い**。「参考」と表示し、毎朝・毎晩取り直す。
- 気象庁週間予報は **11/18 まで**しか届かない。JSON の利用条件は公式に明記がなく、仕様が予告なく変わる可能性があるので、失敗しても Open-Meteo だけで表示が成り立つ作りにする。
- 予報範囲外・オフライン時の代わりに、Open-Meteo Historical で平年値を事前計算して JSON に入れておく。最終取得時刻を必ず表示する。
- 阿蘇・くじゅう・霧島・雲仙など標高1,000m級は平地より大きく寒い。都市の天気だけ見て服装を決めない（F14/F16 の価値の根拠）。

### スポット・イベント情報
- 02 には**要確認**が多い（九年庵の公開日程、ハウステンボスの期間、くまもと花博の会場別内容、西都原・青島のイベント詳細、熊本城ライトアップなど）。アプリでは「要確認」バッジを残し、出典リンクを開けるようにする。確認済みに見せかけない。
- 紅葉見頃は予想日（11/11取得）で、天候で前後する。
- spots.json には**営業時間・定休日・料金・屋内/屋外・夜タグが無い**。F02/F15/F32 を作るには69件にタグを付ける作業（1〜2時間）が要る。営業時間は Google マップのリンクで都度確認する方針にし、アプリで「営業中」を断言しない。
- 日没が17時10分前後と早い。屋外スポットを夕方に入れる旅程は危ない。

### 技術・運用
- 地図タイルはオフライン用に事前保存しない（OSM は禁止、地理院は未確認）。圏外ではリスト表示に切り替え、Google マップのオフラインマップ（九州を事前ダウンロード）を併用。
- Geolocation・Service Worker は HTTPS 必須 → GitHub Pages で配信。file:// では動かない。
- **GitHub Pages の公開リポジトリだと旅程が丸見え**。宿の予約番号・氏名・電話などは JSON に入れない。旅程は端末の localStorage に置き、リポジトリには載せない。
- localStorage は端末ごと・ブラウザごとで、消えることもある。旅程のエクスポート/インポート（JSON ファイルやコピー）を用意しておく。
- 静的サイトに API キーを置かない（LLM・Google 系は使わない）。
- 出典表示が規約上必要：地理院タイル（リンクつき）、OSM、Open-Meteo（CC-BY 4.0）、気象庁（「出典：気象庁ホームページ」＋URL）。
- **時間が無い**：11/13 夜までに Must が動かなければ意味がない。出発前にしか役立たない案（F19・F20・F21・F22・F11）は、アプリにせず今チャットで検討する方が早い。
